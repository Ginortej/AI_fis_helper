# ESP + AI: потоковый голосовой мост

ESP32 непрерывно передаёт звук с микрофона в FastAPI по WebSocket. Сервер передаёт его в OpenAI Realtime и сразу возвращает фрагменты аудиоответа ESP. Аудиофайлы не создаются.

## Подготовка

1. Установите зависимости: `poetry install`.
2. В `API_AI_work/.env` задайте `TOKEN_API_AI` (ключ OpenAI) и `ESP_API_KEY` (свой случайный ключ длиной не менее 16 символов). Пример есть в `API_AI_work/.env.example`.
3. Из каталога `API_AI_work` запустите `poetry run python main.py`.
4. Разрешите входящие подключения к порту 8000 в брандмауэре Windows. ESP подключается к `ws://<LAN-IP-компьютера>:8000/ws/esp` с заголовком `X-ESP-Key: <ESP_API_KEY>`.

## Протокол ESP

- После подключения сервер присылает текстовый JSON `{"type":"ready","format":"pcm16","sample_rate":24000,"channels":1}`.
- ESP посылает двоичные WebSocket-кадры с сырым PCM16LE, моно, 24 кГц, без WAV-заголовка. Рекомендуемый размер кадра: 20–100 мс звука (960–4800 байт).
- Двоичные кадры от сервера содержат PCM16LE того же формата и должны сразу попадать в очередь воспроизведения.
- Текстовый JSON `{"type":"clear_playback"}` означает очистить очередь воспроизведения при начале новой реплики пользователя.
- Текстовый JSON `{"type":"audio_done"}` означает конец очередного аудиоответа.
- Текстовый JSON с `type: "error"` сообщает об ошибке. Размер входного кадра ограничен 64 КиБ.

Для ESP нужна прошивка, которая захватывает и воспроизводит именно этот формат. Существующие скетчи не менялись: модель ESP, микрофон и аудиовыход пока не указаны.

## Ограничения текущего этапа

Одна WebSocket-сессия ESP создаёт одну сессию OpenAI. При отключении ESP сессия закрывается. Разговор и аудио не записываются на диск. Полный голосовой цикл требует рабочего ключа OpenAI и совместимого аудиооборудования; локальный тест без них проверяет только протокол и маршрутизацию.
